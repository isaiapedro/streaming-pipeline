# Experimental evidence bundle

This directory contains aggregate results, synthetic seed-level run provenance,
and figures. Raw vital time series, clinical reference rows, credentials,
broker captures, hostnames, and Personal-domain notes are prohibited. Every
figure must be generated by a documented command in `manifest.json`.

## Reproduction

From the academic repository root, create the aggregate benchmark package:

```bash
python3 scripts/run_benchmark.py --signal-seeds 5 --noise-seeds 5 \
  --stable-duration-s 86400 --out benchmark_results.csv \
  --run-log evidence/experiment_runs.jsonl
python3 scripts/aggregate_benchmark.py --input benchmark_results.csv \
  --output evidence/benchmark_aggregate.csv --figures-dir evidence/figures
python3 scripts/build_evidence_manifest.py --mode development
python3 scripts/build_evidence_manifest.py --mode final
```

Development mode always writes an inspectable manifest and records every
release blocker. Final mode is fail-closed: it does not overwrite the manifest
unless the worktree is clean, the installed environment exactly matches all
pinned requirements, the raw/result-log hashes are available, every cell
completed from a clean worktree, and the complete 450-row protocol—including
the 24-hour stable baseline—is present.

For a release, start the benchmark from a clean code commit so every run-log
record captures `worktree_dirty=false`. Generate and inspect the development
package, commit the reviewed generated artifacts, recreate the pinned
environment with `python3 -m pip install --requirement requirements.txt`, and
then run final mode from that clean state. Final mode verifies that the run-log
implementation commit is an ancestor of the current evidence commit and that
every intervening path is under `evidence/`. It records both commit identities,
writes the attestation, and refreshes checksums for a final evidence-only commit.
Do not edit a manifest, run log, or checksum by hand to bypass a blocker.

Live protocol, latency, scale, and approved-reference distribution commands
are frozen in `manifest.json`. An empty metric means unavailable or
inapplicable, never zero. A tier or experiment that was not run remains
`unexecuted`; it must not be described as passed or failed.

The benchmark is a fully crossed 5×5 signal/noise-seed design (25 cells per
scenario and approach). Stable baseline is simulated for 24 hours. Detection
requires a newly opened episode after onset; an alarm already active at onset
does not count as detection. `RESULTS.md` and `FIGURE_CAPTIONS.md` define the
claim boundary and interpretation.

`SHA256SUMS` covers the publishable artifacts in this directory. The manifest's
`benchmark.artifacts` section additionally hashes `benchmark_results.csv`,
which intentionally remains at the repository root and is ignored by Git, and
hashes the run log again as a direct provenance input. Re-run development mode
after iterative changes; use final mode only from the frozen release commit
and its exact environment.
